# 全流程巡检

## 决策顺序

1. **先摸家底**(`site_crawl`):拿到页面、静态资源、表单与接口清单。
   这一步失败就停 —— 站点不可达时继续探测只会得到一堆"连不上"。
2. **再查内容**(`page_diff`):首次执行采集基线,之后每次比对差异。
   发现新增外链、被替换的标题/文案时,记下"从哪个页面来的"。
3. **查误发布**(`sensitive_file_probe`):按本单位的敏感信息定义试落点,
   只做只读下载,拿到内容后再判断真假(不要只看状态码)。
4. **补落点**(`dir_probe`):常见备份/配置/管理入口,同样只读。
5. **最后做漏洞探测**(`nuclei_scan`):模板扫描放在最后,因为它最慢也最容易触发告警。

## 判定纪律

- 只有"响应内容里确实出现了敏感特征"才算泄露;403/404/跳登录页都不算。
- 同一条问题不要拆成多条发现;不同路径的同类泄露算一条,路径写进证据。
- 站点不可达、被 WAF 拦、返回内容与预期不符时,如实说"这一项没验成",不要猜。
- 每一步都把"做了什么、看到什么"留在观察里,最后汇总时才能回溯。

## 收尾

巡检结束后建议直接接 `skill_report` 出报告;需要核对证据时用 `skill_evidence`。
