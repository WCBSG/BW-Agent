# 网站安全巡检智能体（C++ 版）

**一个 exe，双击就能用。** 它自己决定下一步查什么、什么时候该停，
并且**不知道答案时会说"没结论"**，而不是硬报一个"未发现问题"。

- 交付物：`agent\build\网站安全巡检智能体.exe`（单文件，界面与默认规则都在里面）
- 后端：C++20（`agent/src/main/` 约 1.3 万行），**零第三方依赖** —— 不要 Python、不要 Node、不要额外运行库；libstdc++/libgcc 已静态链入，目标机器只要有系统 DLL 即可
- 界面：自建网页界面（起手式 → 任务工作台 → 数据视图，一套纸白），由程序内置
- 数据：默认放 `C:\Users\<用户名>\.bw_agent`

> 想先看「做了哪些验证、怎么复现」？见 [测试报告.md](./docs/测试报告.md)。
> 想跑一遍演示？见 [演示环境.md](./docs/演示环境.md)（配套分级靶场，含未授权禁区）。
> 想看内部怎么搭的？见 [系统架构.md](./docs/系统架构.md)、[工具清单.md](./docs/工具清单.md)。
> 想加一个自己的工具？见 [工具协议.md](./docs/工具协议.md)：声明 + 入口 + 协议，不用改代码。
>
> 多人一起改？先看 [CONTRIBUTING.md](./docs/CONTRIBUTING.md)：分支模型、构建与自检、以及"改代码时不能破的四条线"。

## 一、怎么跑起来

**最省事**：双击 `agent\build\网站安全巡检智能体.exe`（或仓库里的 `启动.bat`）。
它是界面程序：**双击不会弹命令行窗口**，一两秒后界面窗口自动打开，然后：

1. 点右上角「设置授权」→ 把目标主机加进**授权池**（`exp.com` 或 `exp.com:8443`；
   前面加 `!` 表示不允许，可精确到路径如 `!exp.com/admin/`）
2. 勾选「我确认已获得该目标的巡检授权」→ 保存
3. 直接在输入框里说话：

```
把这个站完整巡检一遍        ← 看工作台的实时过程
复测一下                   ← 看发现状态推进（已修复 / 仍未修复 / 判不了）
出报告                     ← 看"报告与告警"页的分级统计与推送
核对证据                   ← 看"证据与闭环"页:每条结论有没有证据、闭环到哪一步
```

**关掉界面窗口 = 退出程序**（后台服务跟着停、端口自动释放，不会留在后台）。
只有 `--debug` 调试时例外：那时窗口只是看板，关掉窗口服务继续跑（想反复打开界面看结果就不用重启程序），
要结束就关掉那个命令行窗口或按 `Ctrl+C`。

**重复双击不会再开第二个**：程序是单实例的（同一个数据目录只允许一个服务进程）。
第二次启动**不新起服务**，只把已经在运行的那个界面窗口叫到前台；窗口已经关掉（最小化到托盘）时，
它按 `instance.json` 里记的端口**重新开一个界面窗口**指过去，不会出现两个服务抢同一份 SQLite。
真要同时开两份（比如同一份数据两条并行演示），加 `--multi`；把 `BW_AGENT_HOME` 指到另一个目录
本来就是两份独立数据，互不影响。

**想看运行日志/排查问题**：加 `--debug` 启动（`网站安全巡检智能体.exe --debug`），
会额外开一个命令行窗口，实时日志就显示在那里。不带 `--debug` 时日志写到
`C:\Users\<用户名>\.bw_agent\agent.log`（UTF-8，超过 2MB 自动轮转一份 `agent.log.1`）。

**第一次会看到界面窗口弹出**：那是本进程自己的 WebView2 窗口（标题栏是
「网站安全巡检智能体 · 端口」，任务栏里是一个独立窗口）。

- **为什么用 WebView2**：界面就是内置网页，但窗口、图标、关闭行为都该归程序自己管。
  早期版本用系统 Edge 的 `--app` 窗口，观感差不多，可那是**别人的进程** ——
  托盘"重新打开"得靠标题去猜是哪个窗口，关窗口也不完全受控。
- **单文件交付不变**：`WebView2Loader.dll`（195KB）以资源形式编进 exe，首次运行时释放到
  数据目录 `bin\` 再动态加载，exe 旁边仍然不需要任何文件。
- **运行时是自己找的**：这台机器上 WebView2 运行时只登记在 32 位注册表视图里，
  64 位加载器按自己的规则会判定"没装"（返回 `0x80070002`），所以程序会直接把
  `C:\Program Files (x86)\Microsoft\EdgeWebView\Application\<版本>` 作为
  `browserExecutableFolder` 传过去。
- **装不了也能用**：运行时缺失或启动失败时自动退回系统 Edge 的 `--app` 窗口，
  界面照样能开（日志里会写明"退回系统 Edge 的 --app 窗口"）。
- 原生窗口（Win32 + GDI+）那条路**已整体移除** —— 一套界面维护两份实现，代价比收益大。

### 数据放哪

| 位置 | 内容 |
|---|---|
| `C:\Users\<用户名>\.bw_agent\` | 发现、报告、运行记录、资产底账、页面快照、审计日志、`pool.json`（授权池）、`approval.json`（审批策略）、`rules\`（检测口径，按域 6 个文件）、`instance.json`（当前实例在哪个端口） |
| 想换位置 | 设环境变量 `BW_AGENT_HOME=D:\某目录` |

首次运行会把**出厂规则**按域写到数据目录 `rules\` 下（`detect` / `sensitive` / `probe` /
`alert` / `org` / `page` 各一个文件）；以后改规则只要改对应的那一个，不用重新编译。
exe 放桌面、放 U 盘、放下载目录都能跑（数据始终在用户目录）。

### 命令行（可选，给懂的人）

```
agent\build\网站安全巡检智能体.exe            零参数 = 启动服务并打开界面
agent\build\agent.exe selftest                自检（当前 116 项，应全过）
agent\build\agent.exe run skill_full_inspection 127.0.0.1:8081    单跑一个技能，结论可复核
agent\build\agent.exe tool dir_probe 127.0.0.1:8081               单跑一个工具
agent\build\agent.exe chat 127.0.0.1:8081     在终端里对话
agent\build\agent.exe rules                   导出当前生效规则
agent\build.bat                          重新编译（需要 g++ / MinGW-w64）
```

> `UI_MODE=off` 只起服务不开窗口（定时任务/自动化用）；`UI_MODE=browser` 强制用系统浏览器
> 打开（排查 WebView2 问题时用）。`BW_WEBVIEW2_ARGS` 可以追加 Chromium 参数，
> 例如显卡/远程桌面环境白屏时加 `--disable-gpu`。
> 依赖只有 Windows 自带 DLL（`WINHTTP / bcrypt / WS2_32 / SHELL32 / ADVAPI32 / GDI32` + 系统 UCRT）
> 加上系统里的 WebView2 运行时（Win10/11 随 Edge 自带）。

### 大模型（可接多家，可在界面里配）

**程序里不带任何厂商的密钥。** 用哪家、用哪个 key，全在「配置 → 模型」里填：

- 三类协议：**OpenAI 兼容**（DeepSeek / Kimi / 通义 / 智谱 / 硅基流动 / OneAPI / vLLM / Ollama …）、
  **Anthropic**（Messages 接口）、**恒脑开放服务**（appKey + appSecret + 智能体 ID，地址填平台首页即可）；
- 可以接入多条，**自己选一条"当前"**在用；不会自动换 —— 用哪家由人定，日志里写清是谁在回话；
- 每条都能**单独测试**：真发一句话，把"地址对不对 / key 对不对 / 模型名对不对"当场说清楚；
- 配置存在数据目录的 `models.json` 里，密钥**读出来是掩码**（`••••xxxx`），界面保存时留空或保持掩码就表示不改。

也可以不用界面：在数据目录或 exe 旁边放一个 `.env`（照根目录的 `.env.example` 填），
首次启动会自动把它变成 `models.json` 里的一条恒脑通道 —— 老部署升级不用重新填一遍。

```
DAS_BASE_URL=https://www.das-ai.com
DAS_APP_KEY=...
DAS_APP_SECRET=...
DAS_USER_APP_KEY=...
```

配好后由大模型负责"决策"；**没有配置或断网时自动降级为本地规则路由**，功能仍然可用，
界面上会如实写明当前是哪种模式。无论如何，结论都来自程序的判定与规则，模型只决定"下一步查什么"。

## 二、能自己加能力(规则 / 技能说明 / 外部工具 / 技能包 / MCP)

和 Claude Code 一样，能扩的东西都放在 `~\.bw_agent` 里，**不用改代码、不用重新编译**。
第一次运行会把**内置技能的说明**导出成 Markdown（都是真东西，见「能力清单」页里的那些技能），
并把**出厂规则按 6 个域拆开落到 `rules\`**：

```
~\.bw_agent\
├─ rules\              检测口径,按域各一个文件(改哪一类就只动那一个;见下)
│   ├─ detect.json       版本、严重等级、内容特征、安全响应头、注入载荷、弱口令
│   ├─ sensitive.json    正文里出现即命中的敏感信息正则
│   ├─ probe.json        探测参数 + 会去尝试的落点与目录
│   ├─ alert.json        什么等级进告警、走哪个渠道
│   ├─ org.json          本单位关键词、文件类型、版本泄露头、错误回显、可疑后缀
│   └─ page.json         目录索引/口令字段标记、篡改判定的外链阈值
├─ skills\skill_*.md   内置技能的说明(何时用/解决什么/用到哪些工具)—— 可直接改
├─ tools\              外部工具:自己按格式建 <工具名>.json
└─ mcp.json            外部 MCP 服务器:自己按格式建(stdio / JSON-RPC 2.0)
```

### 0) 规则本身就是数据：**内置但不硬编码**（并且能在界面里直接改）

代码里只留"判定手法"，"判定什么"全在 `agent\data\rules\`（构建时编进 exe，作为出厂值）。
运行时以**数据目录 `rules\` 下的 6 个域文件**为准：某个文件缺了或某个键没写，就回落到出厂值；
整个 `rules\` 删掉，下次启动会重新按出厂规则生成。

**为什么拆成 6 个文件**：一个 9KB 的 `rules\*.json` 里，改"弱口令"和改"告警阈值"落在同一个文件 ——
版本库里每次整篇变动，也没法把某一类单独交给别人看。拆完之后**改哪一类就只动那一个文件**。

**两种改法**：
1. **界面里改**（推荐）：左侧「规则」页按 6 个域分栏，选中一域就改这一域，点「保存这一域」
   **立即生效不用重启**。
   要直接改原始文件时不用另找入口：**技能页左侧就是 `skills\*.md` 的文件列表**，
   工具页左侧是 `tools\*.json`，MCP 页改 `mcp.json` —— 点文件名就地编辑，
   保存前会**先校验 JSON**、自动留一份 `.bak`。
   页面上还有两个市场入口：**Skill 市场（SkillsMP）** 与 **官方 MCP 市场（恒脑）**，找现成能力直接抄格式。
2. 记事本改：路径同上，改完重启程序。

| 段落 | 管什么 |
|---|---|
| `sensitive_paths` / `dir_candidates` | 要试的落点与目录清单 |
| `signatures` | 内容特征(特征名/类别/等级/命中条件) |
| `weak_headers` | 期望的安全响应头(缺失即判弱配置) |
| `patterns.sensitive` | **敏感信息识别正则**(身份证/私钥/凭据/手机号/邮箱/IP …按本单位口径增删) |
| `weak_passwords` | **弱口令表**(换成你们的历史泄露口令表) |
| `payloads.boolean_diff` | **布尔差分验证载荷族**(恒真/恒假成对,按数据库/框架增族) |
| `markers.dir_listing` / `markers.login_password_field` | 目录索引页与口令字段的识别标记 |
| `severity_levels` / `alerts` | 等级排序、告警阈值与渠道(谁进邮件、谁进站内) |
| `probing` | 探测上限与超时(`max_paths` / `max_dirs` / `max_params` / `timeout_ms` …) |

改完存盘、重启程序即可（**记事本/PowerShell 存的 UTF-8 BOM 会被自动忽略**）；
界面的「规则」页可以省掉记事本，按域保存即热加载。
自己写正则不用猜 —— 有验枪口：

```bat
agent\build\agent.exe regextest "EMP[0-9]{8}" "工号 EMP2024001234"
::  命中: 位置 7,长度 11 → "EMP20240012"
agent\build\agent.exe rules  my-rules.json     :: 导出出厂规则,照着改
```

> 想找现成的能力：界面「配置编辑」页顶部有两个市场入口 ——
> **Skill 市场**（SkillsMP，Codex / Claude 技能包）和**官方 MCP 市场**（恒脑平台的安全工具 MCP，
> 如 ATIP 威胁情报、证书透明查询、多引擎搜索等）。
> 注意合规：市场里的 Nmap / sqlmap / ffuf 这类是**主动攻击性**工具，与本作品"只对授权目标、只读"的定位冲突，
> 建议只接被动情报类，主动类必须在用户显式开启并明确警示后才用。

> 这套"数据驱动"不是摆设：本轮就是靠 `regextest` 抓出了正则引擎的两个真 bug
> （量词重复取错原子、贪婪后不回退 —— 结果是邮箱/私钥头这些形状"本该命中却不命中"）。
> 现在引擎支持字面量、字符类、分组与分支、`* + ? {n,m}`、`^ $`、`(?i)` 与 `(?<![0-9])/(?![0-9])`
> 两种断言，并且会**如实报错**而不是静默不匹配。

### 1) 技能说明（`skills\skill_*.md`）

```markdown
---
name: skill_recon            ← 内置技能名,不要改名(改名就等于新建一个技能)
title: 资产与页面发现
purpose: 把站点的页面、静态资源、接口列成底账……
when: 用户问「这个站有哪些页面」「先摸清资产」时用
tools: site_crawl
---
（正文也是说明文字）
```

- 改 `title / purpose / when / tools` 就生效（重启程序）——**决策时用的就是改过的文字**，
  实现仍在程序里，所以改文字不会把程序改坏；删掉文件即回到出厂说明
- 想让它额外执行一条命令（例如调内部平台接口）：加 `command: 你的命令` 与 `allow: true`
- 想**新增**一个技能：新建 `skills\我的技能.md`，front-matter 里写 `name`（例如 `skill_我的技能`），
  正文写「分几步做」，模型就会把它当方法论照着做

### 2) 外部工具（`tools\<工具名>.json`）

```json
{
  "name": "url_probe",
  "description": "对目标发一次请求,报出状态码与耗时(模型据此决定用不用)",
  "schema": { "type": "object",
              "properties": { "target": { "type": "string" } },
              "required": ["target"] },
  "command": "curl -sS -o NUL -w \"HTTP %{http_code} / %{time_total}s\" --max-time 15 $target",
  "timeout_ms": 20000,
  "allow": true
}
```

- `command` 里的 `$参数名` 会被替换成模型给的参数（参数自动加引号转义，避免拼出第二条命令）
- 整条命令交给 `cmd` 解释，所以 `.cmd` / `.bat` / `.ps1`、管道、重定向都能用（跟你自己敲一样）
- **`allow` 必须为 `true` 才会执行** —— 从别处拷来的配置不会自己跑起来（有意设计的护栏）；
  没开的工具不会出现在能力清单里，日志会写明"改哪个文件才能开"
- 超时、退出码都会记录；输出过长会截断；改完重启程序生效；与内置工具重名会被忽略（内置优先）

### 3) 外部 MCP 服务器（`mcp.json`）

```json
{
  "servers": [
    { "name": "demo", "command": "python C:\\path\\my_mcp_server.py", "cwd": "", "allow": true }
  ]
}
```

- 启动时握手 `initialize` → `tools/list`，把对方的工具登记成 `mcp__<服务器名>__<工具名>`
- 调用时走 `tools/call`，结果（文本块）作为工具输出；服务器返回 `isError` 会被如实标成失败
- 分帧两种都认：**一行一条 JSON**（MCP 规范，官方 Python / Node SDK 就是这个）与
  `Content-Length` 头（LSP 风格）—— 接第三方服务器不会因为分帧不同而"连不上"
- 服务端往 stderr 打日志不会污染协议；`command` 同样经过 `cmd`，用 `.cmd` / `.bat` 包装的启动器也能用

### 自己加完怎么验

```bat
:: 列出能力(外部工具会以 [外部工具] / [MCP] 标出来)
agent\build\agent.exe tools

:: 单独试一个工具(支持 key=value,也支持直接给一段 JSON)
agent\build\agent.exe tool url_probe example.com
agent\build\agent.exe tool mcp__demo__echo_note hello

:: 单独试一个技能(中文名也行)
agent\build\agent.exe run skill_我的技能

:: 界面上也会自动出现:能力清单页 + 模型决策时可用
```

> 位置参数会自动填给这个工具的**必填项**（schema 里有 `target` 就填 target，
> 否则填它唯一的必填字段，例如 MCP 工具常见的 `url`/`text`）。
> 配置文件里的 UTF-8 BOM（记事本存的）会被自动忽略，改完直接存即可。

### 智能体自己也能读状态、改设置

除了上面这些"对站点动手"的工具，还内置了 4 个**本机工具**，让模型能回答
"你授权了哪些站""现在用的是哪个模型""探测超时是多少"，也能按你的话去改设置：

| 工具 | 说一句什么话会用到它 | 能不能改 |
|---|---|---|
| `pool_list` | 「授权列表里有哪些站」「能查哪些」 | 只读 |
| `agent_info` | 「你现在什么状态」「配在哪个目录」 | 只读 |
| `settings_get` | 「当前设置是什么」「探测超时是多少」「现在用的哪个模型」 | 只读 |
| `settings_set` | 「把探测超时改成 15 秒」「每 6 小时巡检一次 exp.com」「切到另一家模型」 | 受限写入，逐条留审计 |

写作边界是刻意的（模型被页面内容诱导也没用）：

- **授权池只能人加** —— 模型没有"往池里加站"的手，只能 `pool_list` 读；
- **审批只能收紧** —— 想切「全部允许」必须人自己在界面上点；
- **周期规则的目标必须已在授权池内** —— 否则"加一条周期"就成了绕过授权；
- 其余设置（检测口径、周期、当前模型）可以改，但每次写入都写审计，
  事后能查出"这条规则什么时候、被谁改掉的"。

### 「把授权列表都巡检一遍」

这句话是确定需求：对池里**每个允许的目标各跑一轮**。程序自己展开（一轮最多 8 个站，
超出会提示再说一次），每站单独建任务、单独设合规边界、单独出一份运行记录；
模型只负责"这个站怎么查"。之前的做法是把这句话当普通一轮跑，
结果只查了焦点那一个站（甚至反问"要查哪个"）—— 因为模型根本看不到池子里有什么。
现在提示词里摊了整份授权池，`pool_list` 也随时能查，两处一致。

## 三、它和「扫描脚本」的区别

| | 扫描脚本 | 本作品 |
|---|---|---|
| 顺序 | 检查项写死，从头跑到尾 | 每做完一步看结果再决定下一步；目标不可达立刻收尾 |
| 结论 | 命中即报，容易把自定义错误页当成"一片敏感文件" | 先用一个不存在的路径**校准出站点默认页**，与之同形的响应一律排除；判定靠**内容特征**而不是文件名 |
| 说不清时 | 报"未发现"（其实是没查成） | 明确说"这次没得出结论"，并说明卡在哪一步 |
| 收尾 | 无 | 复测推进闭环状态 → 报告分级统计 → 证据与闭环核对 |

几个具体手法（都在 `agent/src/main/` 里，可对着代码看）：

- **软 404 校准**：很多站点对不存在的路径返回 `200 + 自定义错误页`，不校准必然大面积误报
- **同形比较**：比对正文时先把数字串抹平，否则带时间戳/计数器的页面会被判成"变了"
- **内容特征判定**：凭据文件、数据库备份、私钥、版本库元数据等按内容特征识别，不靠文件名猜
- **布尔差分验证注入**：对同一参数分别发恒真/恒假条件比对响应差异，只确认"是否存在注入"，不取数据、不修改数据
- **响应头客观判断**：安全响应头、Cookie 属性、版本信息泄露都只看响应头，拿不到头就明说"这项没检查"

## 四、三层结构(为什么它是「智能体」)

```
循环(loop)  ─ 大脑：感知 → 决策 → 行动 → 观察 → 反思 → 收敛      agent/src/main/agent.cpp
技能(skill) ─ 能力：一件事的完整做法与判定                        agent/src/main/skills.cpp  agent/src/main/skills_closure.cpp
工具(tool)  ─ 手：一次原子动作，只做只读取数与客观判断(本机类见下)    agent/src/main/tools.cpp
```

**工具（12 个）**：8 个侦察类 —— `site_crawl` 资产发现 / `sensitive_file_probe` 落点探测 /
`dir_probe` 目录探测 / `page_diff` 内容基线比对 / `nuclei_scan` 安全配置检查 /
`sqli_probe` 注入验证 / `sensitive_scan` 文本敏感信息扫描 / `password_check` 口令强度评估；
4 个本机类 —— `pool_list` 读授权列表 / `agent_info` 读自身状态 / `settings_get` 读设置 /
`settings_set` 受限地改设置。
工具不下业务结论，只如实返回事实；本机类工具不碰被检目标，但**不能扩授权、不能放宽审批、
不能给未授权目标建周期规则**。

**技能（7 个）**：`skill_full_inspection` 全流程巡检 / `skill_recon` 资产与页面发现 /
`skill_leak_check` 敏感信息检查 / `skill_integrity_check` 内容完整性检查 /
`skill_retest` 复测与闭环 / `skill_report` 报告与告警 / `skill_evidence` 证据与覆盖核对。

### 交互上按「主流 Agent」补齐的几件事

- **随时叫停**：执行中输入框旁出现「停止」，信号直达取数通道 —— 正在跑的那一轮在下一次请求前就撒手，
  不必等整个技能跑完；停下时会说清停在第几步、已确认几条风险
- **多会话并行**：授权范围、越界标记、目标基准地址都按线程隔离，审批等待也各占一个槽；
  两个标签页可以各查各的站，A 在巡检时 B 的状态轮询照样 8ms 返回，互不阻塞
- **每轮对话都进运行记录**：纯问答记成「对话」，走技能的记成那个技能的名字；全流程巡检由技能自己记一条，不会重复
- **会话回看**：每轮对话（含附件、停止原因、步数）落进 `threads\`，**左栏就是会话列表** ——
  标题、条数、时间，点一条就回到那次对话并继续在它上面说；「新建巡检」开新会话、「HOME」回起首式
- **左栏可管理**：会话可归档进折叠的「已归档」分区（展开状态记在本机、归档状态存在数据目录，
  换浏览器仍在）；"跑过几轮"这类运行记录在「日志」视图里，不再和会话挤同一列；
  审批策略挪到输入框下方，贴着"这句话怎么执行"
- **布局可调**：左栏 / 右栏之间有可拖动的分隔线（双击回默认），输入区上沿也能拖动改高度；
  设置 → 界面里还有滑杆与开关（左右栏宽度、输入框高度、留痕 / 自动滚动 / 动效），全部记在本机
- **关窗口不退出**：窗口关掉后程序留在**系统托盘**（图标 + 气泡提示），周期巡检继续跑；
  左键双击或右键「打开界面」叫回窗口，右键「彻底退出」才真正结束进程
- **规则与设置分开**：检测口径在侧栏「规则」页，按 6 个域（检测口径 / 敏感信息 / 探测参数 /
  告警与推送 / 单位口径 / 页面与篡改）分栏，**每个域就是一个文件**，保存只写当前这一域并立即重载；
  版式与「设置」完全一致（左导航 + 右表单 + 底部保存）。设置页只剩程序自身的东西
  （界面 / 技能 / 工具 / 模型 / MCP），不再让"改个弱口令"和"改个界面宽度"挤在同一列；
  技能页、工具页都改成「左侧文件导航 + 右侧内容」：第一项是清单，后面每项是一个
  `skills\*.md` / `tools\*.json`，点文件名就地编辑，不用再单独开一个"高级 · 文件"；
  MCP 页同样可编辑 `mcp.json`，并支持「用大模型创建」一条 `mcpServers` 条目
- **附件**：日志 / 配置 / 导出文件直接贴上，文本内容进这一轮输入；截图按原样存档并如实标注
  「当前模型不支持读图」，不假装看懂
- **流式输出**：模型端点边收边推（`net_post_stream`），界面上是分段出现的正文；决策 JSON 不外播
- **原生函数调用兼容**：除提示词约定外，也认 `tool_calls` / `name+arguments` 这类结构化调用

**反思（程序强制，不交给模型）**：

- 观察到"目标不可达 / 不在授权范围 / 连不上" → 立刻停止，如实说明
- 观察到重复动作（工具+参数+结果相同）或连续两步没有新手段 → 判定无进展，收尾
- 停止原因都会被记录并显示：`已给出结论 / 需要用户补充信息 / 无进展 / 预算用尽 / 超出授权范围 / 出错`

## 五、规则是数据,不是代码

`agent\data\rules\` 里放的是"这个单位关心什么"（构建时编进 exe 作为出厂值）：

- `sensitive_paths` 要试的落点清单（默认 36 个）
- `dir_candidates` 要试的目录清单（默认 29 个）
- `signatures` 内容特征定义：特征名 + 业务类别 + 等级 + 指纹标签 + 命中条件（正文包含/路径后缀/最小长度…）
- `weak_headers` 期望的安全响应头与各自等级、影响、修复建议
- `error_signatures` 错误回显特征、`dangerous_methods` 危险方法、`suspicious_tlds` 可疑域名后缀
- `probing` 探测上限与超时

换目标、换单位只要改这个文件，**不用改代码、不用重编译**。报告与界面"生效规则"页都会写明本次用的是哪套规则。
`agent\data\rules\` 缺失时使用内置的同结构默认规则（保证零配置也能跑）。

## 六、合规与安全边界

- **授权域名校验**：不在授权域名内的请求一个都不发（域名是授权单位，端口只用于地址对齐）
- **只读**：只允许 `GET / HEAD / OPTIONS`，不做写入、上传、爆破、利用
- **限速**：默认 2 QPS（`net_set_rate_limit`）
- **全程审计**：每次请求都落 `data\audit.jsonl`（时间、目标、方法、状态、耗时、是否放行）
- **证据去敏**：手机号/邮箱/IP/身份证/卡号/凭据在落盘前就脱敏
- **界面服务只绑 127.0.0.1**，静态资源白名单，路径穿越直接 404

`data\` 下：结果类 JSONL 只追加，配置/记录类一对象一文件。

|---|---|---|
| 发现 Finding | `findings.jsonl` | F-0001 |
| 资产 Asset | `assets.jsonl` | A-0001 |
| 告警 Alert | `alerts.jsonl` | AL-0001 |
| 测试用例 TestCase | `testcases.jsonl` | TC-0001 |
| 任务 Task / 敏感信息定义 | `tasks\` `profiles\` | T-0001 / SP-0001 |
| 内容基线 / 基线差异 | `baselines\` `diffs\` | B-0001 / D-0001 |

| 报告 Report | `reports\` | R-0001 |

发现的状态机：`new → confirmed / false_positive`；`confirmed → fixed → retest_passed / retest_failed`。

`testcases.jsonl` 只作为自建回归用例，不当效果指标。

## 八、界面

打开 `http://127.0.0.1:8765/`（或由 `启动.bat` 打开窗口）：

| 页面 | 看什么 |
|---|---|
| 起手式（首页） | 只问一句「要巡检哪个站」；给目标才开始，右上角是数据视图入口 |
| 任务工作台 | 左：任务列表（进行中/待复核/失败/已完成）；中：逐步执行经过；右：本轮产物（报告、过程要点、留痕、边界） |
| 周期巡检 | 和「设置」「规则」同一套两栏：左边「周期规则 / 权限审批 / 敏感信息定义」三分类，右边只显示这一类。规则页有目标、范围、周期、下次时间、已跑轮次、变化次数，可停用、立即执行、删除；审批页切换策略（选「全部允许」一律先弹警告，卡片和顶栏走同一条路）；定义页维护本单位口径 |
| 报告与告警 | 最新报告的分级统计 + 发现清单（证据/影响/修复建议/复测记录）+ 告警推送情况；右上「导出」支持 5 种格式 |
| 巡检历史 | 任务（授权范围）、运行记录（页数/工具调用/新增发现/触发来源）、内容基线 |
| 资产底账 | 页面/静态资源/接口清单，状态码着色，可按类型筛选 |
| 证据与闭环 | 每条结论是否带证据/影响/修复建议、状态分布、缺证据清单（不含任何"效果指标"） |
| 生效规则 | 本次用的规则来源、内容特征表、落点与目录清单 |
| 能力清单 | 7 个技能与 12 个工具（8 个侦察类 + 4 个本机类）的用途、何时用、用到哪些工具 |
| 规则 / 能力文件 | 「规则」页按域改检测口径（保存即热加载）；技能页、工具页、MCP 页左侧就是各自的文件列表（`skills\*.md` / `tools\*.json` / `mcp.json`），点文件名就地改，JSON 先校验、自动留 `.bak`；技能页与 MCP 页都有市场入口，MCP 还能「用大模型创建」一条服务器配置 |

界面上还有两处常驻入口：`Ctrl+K` 搜索（任务 / 运行 / 发现 / 资产 / 视图，只搜已落盘的数据），
以及左栏的「周期巡检」——有规则在跑时角标会亮。

界面里的原生控件一律自绘，不跟随系统默认：Windows 上的 `<select>` 弹层是系统菜单
（蓝底高亮 + 系统箭头），复选框的勾也是系统画的，和这套纸白界面不是一路。
做法是**保留原生 `<select>` 当"值的真相"**（代码里读 `.value`、监听 `change` 都不变），
在它旁边画同款按钮，弹层挂到 `body` 上（`position:fixed`，不被滚动容器裁掉）；
复选框用 `appearance:none` + 内联 SVG 对勾；主操作按钮统一 `.primary`（墨色实心）。
所以换配色、换字号时不会留下"这一处还是系统样"。

竖向滚动条也不用了：每个能竖着滚的容器，上沿一条 2px 的墨蓝进度线代替它
（宽度 = 视口底部在全文的比例，和播放器顶上那条一个意思）。它只在**真的往下滚了**
的时候出现，停在顶部时收起 —— 否则每个能滚的框都顶着一条蓝线，读起来像随机下划线。
浮层（搜索面板 / 弹窗 / 数据抽屉）打开时，只显示浮层内部那些条，并抬到浮层之上；
关掉浮层时用 `checkVisibility` 判一次可见性，避免"关掉了布局还在"的面板把条留在页面上。

界面与后端只通过 HTTP + SSE 通信，事件协议是三册合同的六个事件
（`message_start / block_start / block_delta / block_stop / tool_status / message_stop`），
所以**换一套前端不用改 C++ 代码**。

界面是一套纸白体系（深色主题已移除：起手式与工作台是同一产品的两个视角，
换屏不该换性格）。层与层之间是透明度 + 6px 浮起的过渡，抽屉从上方压下；
`prefers-reduced-motion: reduce` 下全部动画关闭。

## 八·五、周期巡检（定时巡检 + 基线对比 + 告警）

命题要求「支持定时巡检、基线对比、告警、复测和报告导出」。这一块就是它。

**一条规则 = 一个目标 + 一个巡检范围 + 一个周期。** 范围决定这一轮调哪个技能
（完整巡检 / 只查泄露 / 只查完整性 / 只摸资产 / 只复测），而不是让模型自己猜。

| 环节 | 做法 |
|---|---|
| 调度 | 服务进程内一个后台线程，每秒看一次有没有到点的规则；到点就取 `g_lock` 跑一轮，跑完把下次时间推走 |
| 周期 | 固定间隔 / 每天定点 / 每周定点，三条都能精确算出下一次触发时间；每条规则各自独立 |
| 并发 | 与手动对话共用同一把锁：巡检与对话不会同时动手；抢不到锁就等下一拍，不会把调度线程挂死 |
| 无人值守 | 事件通道置空，界面关掉照样跑；运行记录 `triggered_by = 周期巡检` |
| 基线对比 | 跑完取这一轮的发现，与**同一任务、同一范围**的上一轮比对：新增 / 等级升高 / 本轮未见 / 仍未修复 |
| 首轮 | 同类范围没有上一轮 → 这一轮就是基线，**不告警**（"第一次跑出 5 条"不是"新增 5 条"） |
| 告警 | 有变化才写一条 `alerts`（`kind=周期变化`，带 `new/fixed/persist/escalated` 与逐条变化清单）；没变化什么都不写 |
| 停机 | 服务没开着时错过的周期**不补跑**，重启只把下次时间顺延（避免开机瞬间对目标突发请求） |
| 边界 | 规则的域名就是它的授权凭据：到点先用它设授权范围，跑完把会话原来的范围还原 |

接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/automations` | 规则列表（含 `next_run_at`、`cycle_text`、`run_count`、`change_count`） |
| POST | `/api/automations` | `{"action":"save"\|"toggle"\|"run"\|"delete"}`；带 `id` 时只覆盖传了的字段 |
| GET | `/api/export?format=&report=` | 导出报告：`md` / `html` / `csv` / `json` / `docx` / `pdf` |

**导出怎么做的（如实说明）**：五种格式都从同一份报告 + 同一份发现清单渲染，
所以"页面上的数字"和"文件里的数字"不会有两套统计。
`docx` 由程序自己拼 OOXML 再打成 ZIP（只用 store 不压缩，因此不需要 zlib）；
`pdf` 不自写字体渲染，而是把同一份 HTML 交给本机 Edge / Chrome 的 headless 打印
（Windows 10/11 自带）——拿不到浏览器时会明确告诉你改用 HTML 打印，不会给一个空白文件。

演示周期巡检（把周期设成 1 分钟就能当着评审的面看到第二轮）：

```
1) 左栏「自动化」→ 目标填 127.0.0.1:8081，范围选「只查敏感信息泄露」，周期「固定间隔」填 1
2) 保存 → 卡片上出现「下次 1 分钟后」；到点它自己跑，界面每 8 秒自动跟上
3) 第二轮跑完看结果：与上一轮相比「没有变化」时不写告警；改一下靶站（删掉 /.env）再跑，
   下一轮就会写一条「1 条本轮未见」
```

## 八·六、审批策略（动手之前先问一句）

主流 Agent 都会在调工具之前过一道闸。本作品的这条闸在**程序里**，不在提示词里：

| 策略 | 行为 |
|---|---|
| `询问`（默认） | 每个动作都停下来等用户点「允许 / 拒绝」；界面在输入框上方浮出一条确认条 |
| `全部允许` | 自动放行全部动作；切换时会弹一次警告（它仍受授权池、只读、限速、审计约束） |
| 自定义策略 | 按工具名逐条指定 `允许 / 询问 / 拒绝`，支持 `*` 通配；可存成多份预设（自定义策略 1、2…） |

规则自上而下**第一条命中**说了算；一条都没命中就按「询问」——不会因为漏配而静默放行。
被拒绝不是报错：它作为一条观察交回给模型（"这一步没有得到你的允许，已跳过"），
模型据此换路子或老实收束；等待超过 15 分钟按拒绝处理。
周期巡检时如果策略是「询问」而没人在看，这一轮会就地停下并写进日志 —— 想让它无人值守地跑，就把策略调成「全部允许」。

接口：`GET/POST /api/approvals`（列出 / 激活 / 保存 / 删除策略）、`POST /api/approval`（允许或拒绝某一次请求）。

## 八·七、授权池（能检查谁，由这张表说了算）

「巡检目标」不是一个全局设定，而是**从授权池里挑出来的焦点**：

- 授权池 = 允许访问的主机白名单（`host` 或 `host:port`），存在数据目录的 `pool.json` 里，人可读；
- 池子非空时它就是唯一边界；池子空、本轮也没有授权范围时，**任何请求都不发**；
- 越池的请求在取数通道里就被掐断（连包都不发），同时置一个越权标记，决策循环下一步立刻收束整轮；
- 周期巡检到点时如果目标不在池里，这一轮直接跳过，不擅自扩权。

接口：`GET/POST /api/pool`（`{"action":"add"|"remove","entry":"host[:port]"}`）。
界面上点右上角「设置授权」即可维护这张表；工作台右上角的下拉框就是从池里挑"这一轮看哪个站"。

### 关于界面窗口

宿主是本进程自己的 **WebView2** 窗口（Chromium 内核，随系统 Edge 提供）：

- 窗口、图标、关闭行为都归程序自己管；托盘"打开界面"就是把这个窗口叫回来，
  窗口关掉了还能就地重建一个
- `WebView2Loader.dll` 编进 exe，启动时释放到 `<数据目录>\bin\`；用户数据目录在
  `<数据目录>\webview2\`，不往程序旁边丢缓存
- 运行时目录是程序自己找的（见上），找不到/起不来时退回系统 Edge 的 `--app` 窗口，
  再退到默认浏览器 —— 三级兜底，任何一台机器上双击都得有东西出来
- 页面只能导航到 `127.0.0.1`；`window.open` 被拦下（不在界面里再开窗），
  开发者工具、右键菜单、状态栏、缩放控件都关掉（本机工具不该给这些口子）

原生窗口（Win32 + GDI+）那条路**已整体移除**：一套界面维护两份实现，
样式、交互、快捷键都要对齐两遍，代价远大于收益。

WebView2 的**浏览器数据目录放在用户数据目录下**（`%USERPROFILE%\.bw_agent\webview2`）：
程序目录可能不可写（U 盘只读、Program Files、网络共享），也不该在程序旁边留垃圾；
退回 `--app` 窗口时用的是 `.bw_agent\ui-profile`，早期版本遗留在 exe 旁边的那份会被顺手清掉。

**窗口关闭 → 服务停止**：界面窗口是本程序自己开的，关掉就调 `http_stop()` 收摊，
所以双击运行不会出现"窗口关了但端口还被占着"的僵尸进程。
有托盘时常驻（关窗只是收起来，右键托盘图标可重新打开或彻底退出）；
`--debug` 调试时同样只收起窗口，服务继续跑。
降级到"默认浏览器打开"时拿不到窗口句柄，这种模式下不做自动停止（用 `serve` 命令运行的情况也照旧）。

### 单文件是怎么做到的

`agent/tools/mkres.cpp` 在构建期把 `agent/ui/` 三件套 + 图标 + 出厂规则转成一个 C++ 数组
（`agent/build/resources.cpp`），与源码一起编译链接，所以 exe 自己就能提供界面与规则。
运行时**磁盘优先、内置兜底**：放一份 `ui\index.html` 或 `rules\*.json` 在旁边就能覆盖内置版本，
方便换界面、换检测范围，而不需要改代码。

## 十一、已知边界(如实说明)

- 落点探测按默认清单（36 个）与目录清单（29 个）进行，不做字典爆破；未命中不代表绝对没有其他路径
- 注入验证只做布尔差分与错误回显判定，属于"是否存在"级别的确认，不做进一步利用
- 单次巡检按 2 QPS 限速，站点较多时耗时以分钟计
- 大模型未配置时走本地规则路由，只能覆盖常见意图
