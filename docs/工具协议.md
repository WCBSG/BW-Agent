# 工具协议

这一页回答一件事：**一个工具是怎么被认出来、又是怎么被调用的。**
结论先说：工具是「数据 + 入口 + 协议」，不是写死在程序里的函数名。

## 三层

```
声明(JSON)             入口(entry)              协议(protocol)
data/tools/<名字>/      exec / http / builtin    argv / json-stdio / json
  <名字>.json
```

- **声明**说清「这个工具叫什么、解决什么问题、收什么参数」。
- **入口**说清「它到底是个什么东西」：本机进程、HTTP 端点，还是程序内实现。
- **协议**说清「参数怎么交给它、结果怎么读回来」。

声明和入口放在一起即可：内置工具共用主程序自己（`source: "@app"` → `agent.exe toolhost`，按请求里的 `tool` 字段分派），
你自己加的工具也可以用独立的 exe —— 两种形态都认，程序不关心入口有几份。

## 目录长什么样

```
<数据目录>\tools\
├─ bw_tools\
│   ├─ fs_read.json        声明(source = "@app",由主程序以 toolhost 形态执行)
│   ├─ dir_probe.json
│   └─ ...                 15 份声明
└─ 你自己加的工具\
    ├─ 名字.json
    └─ 名字.exe            自己的入口(可以继续一个工具一个 exe)
```

`<数据目录>` 默认是 `C:\Users\<用户名>\.bw_agent`；仓库里的 `agent\data\tools\` 是出厂内容，首次运行会铺到这里。

> 出厂声明（`bw_tools\` 下那些）每次启动都会被覆盖成程序自带的那份 —— 它们是"程序有哪些能力"的一部分。
> 要做自己的工具，另建一个目录（下面例子里的 `es\`），程序会把 `tools\` 下每个子目录里的 `*.json` 都加载进来，
> 目录名不影响工具名（以声明里的 `name` 为准）。

### 例子：把本机的 Everything(es.exe)接成工具

Everything 的命令行版 `es.exe` 只是客户端，索引在 Everything 服务里 —— 所以它不适合捆绑进 exe，
而是由使用者自己放。放好之后模型就能像调内置工具一样调它：

```
<数据目录>\tools\es\
├─ es.exe        ← 从 https://www.voidtools.com/downloads/ 取(或直接复制 Everything 安装目录里的那份)
└─ es.json       ← 下面这段
```

```json
{
  "name": "es_search",
  "kind": "外置 · 本机",
  "readonly": true,
  "description": "用 Everything 在本机快速找文件或程序(回答「这台机器上有没有 nuclei / 某个工具装在哪」)。query 用 Everything 语法;只读检索,不运行被找到的程序。",
  "source": "~/tools/es/es.exe",
  "schema": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "如 nuclei.exe、ext:exe python" },
      "limit": { "type": "integer", "minimum": 1, "description": "最多返回多少条,默认 20" }
    },
    "required": ["query"],
    "additionalProperties": false
  },
  "entry": {
    "type": "exec",
    "path": "~/tools/es/es.exe",
    "args": ["-n", "${limit:-20}", "$query"],
    "protocol": "argv",
    "timeout_ms": 15000
  }
}
```

`~/` 展开成数据目录；`$query` 是必填参数，`${limit:-20}` 表示"没给就用 20"。
放好后重启程序（或到「设置 → 工具」点重新载入），`agent.exe tools` 里就能看到 `es_search`。

## 声明

```json
{
  "name": "fs_read",
  "kind": "外置 · 本机",
  "readonly": true,
  "description": "按行读一个文本文件……",
  "source": "@app",
  "schema": {
    "type": "object",
    "properties": {
      "path":      { "type": "string" },
      "startline": { "type": "integer", "minimum": 0 },
      "endline":   { "type": "integer", "minimum": 0 }
    },
    "required": ["path"],
    "additionalProperties": false
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 工具名，模型看到的就是它 |
| `description` | 是 | 说明书：什么时候该用。措辞直接决定模型会不会选它 |
| `schema` | 否 | 参数形状；程序按 `type` / `required` 校验，缺参数当场拒绝 |
| `readonly` | 否 | `true` = 不改动任何东西。审批策略「允许只读」据此自动放行 |
| `source` | 否 | 入口路径。可写 `~/tools/...`（相对数据目录），也可写绝对路径 |
| `impl` | 否 | 程序内实现的名字。入口 exe 缺失时用它兜底，功能不会凭空消失 |
| `allow` | 否 | 默认 `true`；写 `false` 可以「只识别不启用」 |

`source` 也可以省掉：程序会在声明文件旁边找 `<name>.exe` / `<impl>.exe`，找到就用。

## 入口

| type | 什么时候用 | 写法 |
|---|---|---|
| `exec` | 本机脚本 / 独立 exe | `"path": "~/tools/x/x.exe"`，或 `"path": "cmd /c ..."` |
| `http` | 内部平台的接口 | `"url": "http://127.0.0.1:9000/tool"` |
| `builtin` | 程序内实现 | 不写 `entry`，只写 `impl` |

## 协议

### 1) `json-stdio`（推荐，默认）

程序把一份调用 JSON 写进工具的 stdin，从 stdout 读一份结果 JSON。

**请求**

```json
{
  "tool": "fs_read",
  "args": { "path": "rules/detect.json", "startline": 0, "endline": 40 },
  "context": {
    "data_dir": "C:\\Users\\me\\.bw_agent",
    "app_dir":  "C:\\path\\to\\程序目录",
    "cwd":      "C:\\Users\\me\\.bw_agent"
  }
}
```

**应答**

```json
{
  "text": "文件 X 的第 0 到 40 行（共 156 行）\n----\n……",
  "say": "读到了第 0 到 40 行。",
  "data": { "path": "...", "totalLines": 156, "startLine": 0, "endLine": 40 },
  "is_error": false
}
```

- `text`：给模型看的正文（会被当成「观察」喂回决策循环）。
- `say`：给人的一句话汇报；不写就用 `text`。
- `data`：给界面渲染结构化卡片用，可省略。
- 只输出纯文本也认：stdout 不是 JSON 时，整段当 `text`。

### 2) `argv`

参数按 `args` 数组展开进命令行，`$参数名` 会被替换成实际值（自动加引号、转义），stdout 原样作为结果文本。
适合「已经有现成命令行工具」的场景：

```json
"entry": {
  "type": "exec",
  "path": "whois.exe",
  "args": ["--json", "$domain"],
  "protocol": "argv"
}
```

### 3) `json`（HTTP 专用）

POST 上面那份请求 JSON，应答同上。

## 加一个工具

```powershell
# 1) 建目录
mkdir "$env:USERPROFILE\.bw_agent\tools\my_tool"

# 2) 放声明
@"
{
  "name": "my_tool",
  "kind": "自建",
  "readonly": true,
  "description": "查一下内部资产表里的主机归属。",
  "source": "~/tools/my_tool/my_tool.exe",
  "schema": { "type": "object", "properties": { "host": { "type": "string" } }, "required": ["host"] }
}
"@ | Set-Content -Encoding UTF8 "$env:USERPROFILE\.bw_agent\tools\my_tool\my_tool.json"

# 3) 放入口(exe / bat / cmd 都行),它只要会读 stdin 的 JSON、往 stdout 吐 JSON
copy my_tool.exe "$env:USERPROFILE\.bw_agent\tools\my_tool\my_tool.exe"
```

重启程序（或界面里点「重新加载扩展」）就能在能力清单里看到它，模型也能调用。
**不用改 C++，不用重新编译。**

## 单独验收一个工具

```powershell
cd agent\build
.\agent.exe toolhost fs_read   # 工具名可省,请求里带 tool 即可

# 标准输入就是协议本体
'{"tool":"fs_read","args":{"path":"rules/detect.json","startline":0}}' | .\agent.exe toolhost
```

输出就是上面那份应答 JSON。主程序调用走的是同一条路。

## 安全边界（不变）

- 工具进程只拿到「数据目录 / 程序目录」这两个根，读文件不能越界；写只允许数据目录。
- 会改动东西的工具必须 `"readonly": false`，审批策略「询问」下仍会先问人。
- `allow: false` 的工具只登记不执行。
- 每个工具都是一次独立进程：它崩溃不会拖垮智能体，也不会把上一次的状态带进下一次。
