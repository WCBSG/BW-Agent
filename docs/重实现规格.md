# 网站安全巡检智能体 · 重实现规格

> 目的：给一个**全新项目**做实现依据，只保留当前真正在跑的设计，不背负任何历史包袱。
> 读完这份文档，应当能在不参考旧代码的前提下做出行为等价的实现。
> 旧实现是 C++20 + Win32 + 内置 WebView2 的单文件 exe，但**技术栈可以换**，
> 本文按"契约 / 行为 / 数据"描述，凡是绑定 C++/Win32 的地方都会注明"实现备注"。

---

## 一、这是个什么东西

一个**跑在本机的网站安全巡检智能体**。使用者给它一句话（"看看 127.0.0.1:8081 有没有敏感文件泄露"），
它自主决定调哪个技能/工具、读回来的结果够不够下结论，最后交出**每条都带证据**的结论。

三条不能丢的特征：

1. **边界是硬的**：所有对外请求必须落在"授权池"内，池外一个字节都发不出去（在取数层拦，不靠提示词）。
2. **结论必须有证据**：没有响应片段、状态码差异、链路环节的"发现"一律不落库。
3. **决策来自模型**：模型调不通就如实报错，**不允许**用关键词规则顶替（旧版有过，已删）。

它**不是**：漏洞利用工具（不做 getshell、不取数据、不写数据）、不是扫描器的套壳（技能是确定性流程，
但"下一步做什么"由模型决定）、不是 SaaS（纯本机、无账号、数据全在本地目录）。

## 二、运行形态

| 形态 | 说明 |
|---|---|
| 桌面应用 | 双击 exe → 起本地 HTTP 服务（默认 `127.0.0.1:8765`，占用则 8766…8775）+ 打开内置 WebView2 窗口 |
| 纯服务 | `serve [域名] [端口] [--no-ui]`，界面用浏览器打开 |
| 命令行 | `run <技能/工具> <目标>`、`tool <工具> <k=v>`、`chat <域名>`、`manifest`、`rules`、`tools` |
| 工具宿主 | `toolhost`：读 stdin 的 JSON、写 stdout 的 JSON，供声明式工具以 `source:"@app"` 回调自己 |

进程模型：

- **单实例**：启动时抢占一个全局锁（按数据目录区分）。已有实例则把它叫到前台后退出；`--multi` 强制多开。
- **内置 HTTP 服务**：自己实现（不是 libevent/asio），只绑回环。
- **决策循环跑在 HTTP 请求线程上**（SSE 长连接），每个会话一个 agent 实例、一把会话锁。
- 定时任务有独立的调度线程与独立的 agent 实例，不和用户会话抢上下文。

## 三、数据目录

`%USERPROFILE%\.bw_agent`，可用环境变量 `BW_AGENT_HOME` 覆盖。**整个目录可以整份拷走。**

```
<bw_agent>\
├─ agent.log                 运行日志（长驻形态才写）
├─ pool.json                 授权池（唯一一份"能查谁"的凭据）
├─ models.json               模型接入配置（含密钥，使用本设备凭证加密，只在本地）
├─ mcp.json                  外部 MCP 服务器清单
├─ approval.json             审批策略（内置三条 + 用户自定义）
├─ profile.json              当前生效的"本单位敏感信息定义"（可选）
├─ rules\                    6 个规则域，一个域一个文件
│   ├─ detect.json           等级、内容特征、期望安全头、布尔差分载荷、弱口令表
│   ├─ org.json              关键词、敏感文件类型、版本泄露头、错误特征、危险方法、可疑 TLD
│   ├─ page.json             目录索引标记、登录表单特征、外链阈值
│   ├─ probe.json            探测预算 + 敏感落点清单 + 目录候选
│   ├─ sensitive.json        敏感信息正则（类型 / 正则 / 等级）
│   └─ alert.json            告警阈值与渠道名
├─ skills\<名字>\SKILL.md     技能说明（front-matter + 正文判据）
├─ tools\<目录>\<名字>.json    工具声明（19 份出厂 + 用户自加）
├─ chat\<对话id>.jsonl        对话转录（message / event / meta 混存，只追加）
├─ time\<任务id>\<时间戳>.jsonl 定时任务的每次运行记录
├─ WebView2Loader.dll        从 exe 释放（WebView2 用）
├─ webview2\                 WebView2 用户数据目录
└─ 各集合的 .jsonl            findings / assets / runs / reports / alerts / baselines / …
```

**出厂文件与用户文件的界线**（重实现时必须守住）：

| 类别 | 铺开策略 | 理由 |
|---|---|---|
| `rules\`、`skills\` | **缺了才补** | 这是给人改的，不能冲掉使用者的改动 |
| `tools\` | **每次启动覆盖** | 它是"程序有哪些能力"的一部分；残留旧声明会让工具悄悄失效 |
| 可执行文件（`.exe`/`.dll`） | 每次覆盖 | 同上 |

## 四、启动装配顺序（有依赖，不能换）

```
1. 解析命令行（摘掉 --debug / --multi）
2. 初始化路径（exe 目录 / 数据目录）
3. 打开日志（长驻形态才写文件）
4. 单实例抢占（失败 → 叫前台 → 退出）
5. 铺出厂数据到数据目录（selftest 除外）
6. tools_init()          工具注册表（内置 19 个实现的入口表）
7. skills_init()         技能注册表（内置 7 个）
8. rules_init()          6 个规则域
9. ext_bootstrap/load    技能包、MCP 清单（工具声明不在这里，见第 6 步）
10. llm_init()           模型配置
11. net_init()           WinHTTP 会话
12. 分派子命令 / 起服务
```

为什么顺序重要：工具声明里可能写"入口在同目录的 exe"，exe 没铺开就认不出入口，能力会**悄悄**退回内置实现。

## 五、授权与安全边界（本项目的心脏）

### 5.1 授权池

`pool.json`：

```json
{ "hosts": ["127.0.0.1:8081", "!127.0.0.1:8081/l0/", "example.gov.cn"] }
```

- 一条 = 一个允许的主机（可带端口、可带路径前缀）。
- `!` 开头 = **明确禁止**，优先级高于允许。
- 判定顺序：先看有没有命中禁令 → 再看有没有命中允许 → 池非空时两者都没命中 = **拒绝**（默认关门）。
- 路径匹配：`/admin/` 命中 `/admin/` 与 `/admin/x`；`/a.php` 只命中它自己（可带 `?`/`#`）。
- 池子**不能**由模型改（没有写接口）；只能人在界面上加。

### 5.2 取数层的三道闸

所有对外请求必须走同一个通道（`tools_io_t` 的 `fetch/fetch_ex`），它内部依次做：

1. **授权校验**：按 5.1 判定；拒绝则**不建立连接**，并置"越权标记"。
2. **只读校验**：默认只允许 `GET/HEAD/OPTIONS`（可配）。非只读请求直接拒。
3. **限速**：默认 2 请求/秒（全局），`wait = last + 1000/qps - now`。

之后才真正发请求，并：

4. **审计**：每一条都写 `audit.jsonl`（时间、动作、目标、是否放行、详情、任务/运行编号）。
5. 记 `http_calls` 计数（报告里的"发了几次请求"用它）。

### 5.3 越权 = 整轮中止

- 任何一次请求被拒 → 置 `violation=1`。
- 决策循环在**下一步之前**检查：发现越权 → 立刻停止整轮，输出"有请求越出授权池，已按合规要求立刻停止整轮"，不再尝试任何动作。
- **这条规则要求"发现型"请求必须先预筛**：爬虫/目录探测/敏感落点这类"按清单挨个试"的动作，
  必须先用**无副作用的**"这个 URL 能不能取"询问（同一套边界、不产生请求与审计）过滤候选，
  否则站内一条被 `!` 排除的链接会毁掉整轮。这是踩过的坑，重实现时务必保留预筛。

### 5.4 界面接口的鉴权

本地 HTTP 只绑回环，但**用户浏览器里的任何网页**都能向 `127.0.0.1` 发简单请求，所以还要：

1. **Host 校验**：必须是 `127.0.0.1:<port>` / `localhost:<port>`。
2. **Origin 校验**：有 Origin 时必须是同源。
3. **进程级令牌**：每进程随机；页面 `<meta name="bw-token" content="...">` 注入，
   WebView2 打开 URL 时同时带 `?t=`；前端优先读 URL 参数（避免重启后旧页面用过期令牌）。
   `/api/*` 除 `/api/health` 外都要求令牌。
4. **POST 只收 JSON**（`Content-Type: application/json`），挡住表单式 CSRF。
5. 请求体大小上限、路径白名单（`/api/config` 只能读写数据目录里指定形态的文件）。

## 六、决策循环

一轮对话 = 一次完整循环。状态机：

```
感知(用户输入 + 历史 + 已得观察)
  ↓
反思(程序侧硬判定：越权？打转？预算？)   ← 先于决策
  ↓
决策(模型；失败即按失败收尾)
  ↓
行动(技能或工具；审批 → 执行 → 观察)
  ↓
回填观察，回到"反思"
  ↓
收敛(给结论 / 需要补充 / 无进展 / 预算用尽 / 出错 / 被叫停)
```

### 6.1 收敛判定（程序侧，不看模型说什么）

| 条件 | 停止码 | 停止原因（人话） |
|---|---|---|
| 用户点了停止 | `CANCELLED` | 用户中途叫停 |
| 取数层越权标记（任一步） | `OUT_OF_SCOPE` | 有请求越出授权池… |
| 观察里出现"不在授权池内/不在授权域名内" | `OUT_OF_SCOPE` | 目标不在授权范围内… |
| **执行失败**的观察里出现"全部请求失败/一次都没成功/目标不可达/连不上端口/域名解析不了" | `OUT_OF_SCOPE`（语义为"没意义再跑"） | 目标不可达… |
| 这一步与历史某一步"同名 + 同参 + 同结果" | `NO_PROGRESS` | 这一步的动作与结果此前已经出现过… |
| 连续 2 步都是**技能**且没用到新手艺 | `NO_PROGRESS` | 连续两步用的都是前面已经用过的手段… |
| 模型决策失败 | `ERROR` | 模型不可用：<具体原因> |
| 模型给出 `final` | `ANSWERED` / `ANSWERING_ONLY` | 已给出结论 / 纯问答 |
| 模型给出 `ask` | `NEED_USER` | 需要用户补充信息 |
| 步数用完 | `BUDGET` | 达到本轮步数上限（N 步）… |

**注意两个细节**：

- "不可达"只在**失败的那条观察**上判定。全文子串匹配会把"2 个地址返回异常(5xx)"误判成整站不可达，整轮白跑。
- "连续重复"的闸**只对技能生效**。工具不一样：`http_get` 连着读十个页面、`record_finding` 连着记三条，
  正是"顺着线索往下查"的样子，不该被当成打转。

### 6.2 预算

- 默认 **10 步**（`MAX_STEPS_DEFAULT`）。
- 提示词里明确写"最多 N 步 / 已用 K 步 / 还剩 M 步" —— 模型原来不知道自己只剩几步。
- 观察进提示词有字节预算：单步 ≤2500、总量 ≤12000（超出截断，中间省略、保留头尾）。

### 6.2.1 上下文占用与压缩

提示词按 token 估算占用（CJK 一字≈1、ASCII 约 4 字节 1），和模型窗口比较：

- 每个模型可配 `context_tokens`（窗口）；没配按 128000 算。
- **留给响应的那一截**固定为窗口的 1/8，界面用斜纹画在进度条末端；只有前 7/8 可被提示词占用。
- 占用环（输入框右侧）显示 `已用 / 窗口`，70% 转黄、90% 转红；每轮 `message_stop` 与
  `/api/status` 都带 `context{used,window,reserve,compressed}`，不必额外轮询。
- **压缩（compaction）**：把较早的轮次压成一段中文摘要，原文不再进提示词，摘要以
  "## 更早的对话(已压缩成摘要)" 插在历史之前。留最近 2 轮原文。
  - 手动：输入框右侧浮层里的「压缩对话」→ `POST /api/compact?sid=`。
  - 自动：一轮结束若占用超过 `(窗口 - 预留) × 90%`，自动压一次 —— 超窗是硬失败，不能等它爆。
- 摘要优先让模型写（≤300 字）；模型不可用时退化为"用户说了什么 → 结论/停止原因"的摘录，
  仍然远小于原文，且不丢线索。
- 压缩结果写进会话 `context{summary,compacted_turns,at,tokens}`：重开对话时摘要仍生效，
  并作为一条标记显示在会话开头（"更早的对话已压缩成摘要（N 轮）"）。
- 压缩是**可见**的动作：不偷偷改上下文，用户能看见压过几轮、摘要是什么。

### 6.3 手动巡检撞上"已巡检且无变化"

程序侧规则（不是提示词，避免模型超时降级后悄悄收尾）：

- 触发条件：**不是**无人值守 且 用户这句话含"巡检" 且 最近一条观察含
  "与基线一致 / 指纹未变 / 未发现改动 / 没有发现变化"。
- 动作：用提问工具问一次，选项固定为「继续完整巡检 / 只看增量 / 先不做」，默认「只看增量」。
- 同一轮只问一次；答案作为观察回填给模型，由它接着决定。
- 无人值守（定时/自动巡检）**不提问**：没人可答，问了只会卡住整轮；只做增量并如实写进结论。

## 七、提示词契约

一次决策 = 一条 prompt，**要求模型只输出一个 JSON 对象**（无解释、无代码块）。

### 7.1 结构（顺序固定）

```
你是「网站安全巡检智能体」的决策内核:自主判断下一步,不跑固定流程。

## 判断(一步一动作,拿到结果我会再问你一次)
1. 先定意图:巡检 / 复测 / 出报告 / 只是提问。
2. 观察结果够下结论就直接 final,不为凑步数再跑。
3. 否定结果(不可达/未授权/被排除/超时/被拒)只能如实说明,不得推成「安全」。
4. 同一动作已有结果且无变化,不再重复,直接收尾。

## 选择
优先技能(一次调用即跑完、直接给结论);技能覆盖不到才单独用工具。
全流程巡检已含完整性/敏感信息/目录/模板,别再单独重跑这几个技能。
技能只是成套路的第一步:跑完还有线索(页面、接口、外链)就用工具接着看,别急着收尾。
非只读工具会弹审批、可能被拒:被拒按否定结果处理,不要换个说法再试。
args 只填必需参数,不要枚举长列表。

## 深入分析(需要真判断时)
- 看底账:asset_list 拿页面清单;http_get 读状态、响应头、标题、正文与链接。
- 篡改:跨页比对标题/关键文案/外链/脚本来源,再结合基线差异;新增外域或裸 IP 最可疑。
- 漏洞:看响应头缺失、错误回显、危险方法、参数回显;有参数就上 sqli_probe 做差分。
- 多步链:上一步拿到的路径/参数就是下一步的输入,链上每一环都要写进证据。
- 有结论就用 record_finding 落库(等级/证据/影响/修复),再决定继续还是收尾。

## 本轮预算
最多 10 步,已用 K 步,还剩 M 步。

## 可用技能
- <名字>(<标题>) —— <作用>
  什么时候用:<触发词>
  做法:<SKILL.md 正文，截断到 480 字节，换行压成 " / ">

## 可用工具
- <名字>(<参数名,参数名>) —— <描述前 150 字节>…

## 授权范围(硬约束)
本轮焦点:<主机>
<授权池全文>
池外不动手,直接说明。

## 什么时候该问            （无人值守时换成"## 无人值守"）
用户手动让查某个站时,如果它已经巡检过、这次比对又没变化,必须先 ask_user 问清楚
(选项:继续完整巡检 / 只看增量 / 先不做),不要自行收尾。
其它情况不要打断用户。

## 最近的对话(按时间顺序,供你理解指代)
- 用户:…
- 你:…

## 已经拿到的观察结果(按时间顺序)
--- 第 1 步 [工具名] ---
<结果文本>

## 用户本轮输入
<用户这句话>

## 输出:只输出一个 JSON,无解释、无代码块
{"skill":"技能名","args":{…}} 或 {"tool":"工具名","args":{…}}
或 {"final":"中文回答"} 或 {"ask":"需用户补充什么"}
可加 "reason":"一句话理由"。
final 要像跟人汇报:先用两三句自然语言说清「查了什么、发现几条、最要紧的是哪条」,
再给证据位置、影响与下一步;不要只回「见上面的结果」「已生成报告」。
```

### 7.2 体积纪律

**提示词体积直接换算成首字节延迟**（实测同一模型：输入 3.6KB→7.7s，14.4KB→60.8s）。所以：

- 系统提示词本体 ≤1500 字节；
- 技能正文进提示词 ≤480 字节/条（做法由实现决定，不必每步都念）；
- 工具清单每行「名字(参数名) —— 一句用途」，描述截断；
- 观察有字节预算；对话历史只带最近 6 轮、每轮 600 字节。

### 7.3 模型输出容错

模型很爱加解释、包代码块、把 JSON 写坏。解析按"从可信到宽泛"逐级尝试：

1. 整体是 JSON → 用它；
2. 从文本里找第一个平衡的 `{…}` 段；
3. 剥 ```json 代码块再试；
4. 认 `tool_calls` / `name`+`arguments` 这类原生函数调用形态；
5. 都不成 → 判失败（记 `llm_bad_output` 审计），**不猜**。

判为决策 JSON 后，**不再把这段文字当正文往界面吐**（否则用户会看到 `{"skill":…` 一个字一个字冒出来）。

## 八、技能（7 个）

技能 = **确定性的成套流程**，一次调用跑完，直接给结论。模型只决定"用不用、用哪个"。

| 名字 | 标题 | 触发词 | 干什么 |
|---|---|---|---|
| `skill_full_inspection` | 全流程巡检 | 整体看看 / 跑一遍巡检 / 做安全体检 | 摸底 → 完整性 → 敏感文件 → 目录 → 模板扫描，串成一轮 |
| `skill_recon` | 资产与页面发现 | 有哪些页面 / 先摸清资产 / 站点结构 | 爬站，产出页面/静态资源/接口底账，标 `from`（从哪页发现） |
| `skill_leak_check` | 敏感信息检查 | 查敏感文件 / 有没有配置泄露 / .env 能不能下 | 按落点清单只读取回，按**内容特征**判定泄露 |
| `skill_integrity_check` | 内容完整性检查 | 网页有没有被改 / 有没有挂马 / 和之前比变了没 | 首次建基线，之后比差异（标题、正文、外域主机） |
| `skill_retest` | 复测与闭环 | 复测一下 / 修好了吗 / 再看看那几个问题 | 取未闭环发现，用**同一判据**重测，回写状态 |
| `skill_report` | 巡检报告 | 出报告 / 导出报告 / 把结果整理一下 | 汇总分级 + 发现引用 + 落盘 + 告警 |
| `skill_evidence` | 证据与覆盖核对 | 核对证据 / 结论靠得住吗 / 哪条没证据 | 逐条查证据/影响/修复是否齐，不计算任何指标 |

### 8.1 全流程巡检的顺序与理由

1. **先摸家底**（`site_crawl`）：失败就停 —— 站点不可达时继续探测只会得到一堆"连不上"。
2. **再查内容**（`page_diff`）：首次采基线；之后比差异。
3. **查误发布**（`sensitive_file_probe`）：按本单位定义试落点，只读下载。
4. **补落点**（`dir_probe`）：备份/配置/管理入口。
5. **最后做漏洞探测**（`nuclei_scan`）：最慢、最容易触发告警，放最后。
6. **注入验证**（`sqli_probe`）：只对带参数的地址做，非破坏布尔差分。
7. **逐页正文敏感信息**（`sensitive_scan`）：把每页正文交给同一套规则集。
8. **汇总**：一次给出"资产 / 完整性 / 暴露面 / 敏感信息 / 配置漏洞"五段式结论。

### 8.2 判定纪律（所有技能通用）

- **只有响应内容里确实出现敏感特征才算泄露**；403/404/跳登录页都不算。
- 200 但内容是伪装页/错误页 → 不算（软 404 校准，见 9.2）。
- 同类问题合并成一条，不同路径写进证据。
- 目标不可达、被 WAF 拦、内容与预期不符 → 如实写"这一项没验成"，不要猜。
- 复测**不改变判据**：原判据仍命中 = 未修复；不再命中且站点正常 = 已修复；
  站点下线/大改版 = 判不了（`unknown`），不擅自推进状态。

### 8.3 技能的可扩展形态

`skills\<名字>\SKILL.md`：

```markdown
---
name: skill_xxx
title: 中文名
purpose: 一句话说明解决什么问题
when: 什么时候该用（写用户会说的话）
tools: site_crawl,sensitive_file_probe
---

# 标题
判据:
- …
```

- 同名内置技能存在时，**只覆盖说明文字**，实现仍是内置的（改文字改不了行为，但能让模型更懂什么时候用它）。
- 技能包只提供"方法与判断"：正文进提示词，由模型按步骤用工具去做。
  （早期版本允许技能包带 `command` 直接跑一条 shell 命令，这套机制已删除：
  它与工具层的 `entry` 声明并存，等于两套执行逻辑各修各的 bug。写这份规格时
  不要重新引入"技能=命令"。）

| 类别 | 工具 | 特点 |

### 9.2 关键判定逻辑（重实现时最容易被做错的部分）

**软 404 校准**（所有路径探测的前提）

很多站点对不存在的路径返回 `200` + 自定义错误页。不先校准，就会把一片"首页/错误页"当成"一堆敏感文件"。

做法：先请求一个**确定不存在**的路径 → 记下状态码、字节数、抹平数字后的正文骨架；
后续候选命中时与之比对（字节数接近 + 骨架相似度超过阈值 ⇒ 判定为"不存在"）。

**`dir_probe`**：目录索引标记（规则 `markers.dir_listing`）、登录表单特征、暴露文件；
软 404 校准；被 `!` 排除的候选**先筛掉再请求**。

**`sensitive_file_probe`**：落点来自 `probe.sensitive_paths` + 本单位追加；
逐个只读取回；判据是**内容特征**（不是文件名、不是状态码）；同样预筛 + 软 404 校准。

**`page_diff`**：首次 = 采基线（只存指纹与快照引用，不存全文）；之后比差异：
新增外域主机（尤其裸 IP）最可疑 → 正文被替换/插入次之 → 只有时间戳/随机串变化 → 忽略。

**`nuclei_scan`**：内置检查为底（安全响应头、Cookie 属性、版本泄露、错误回显、允许的方法、混合内容），
本机装了 `nuclei` 再叠加模板扫描；同一模板打到同一地址只留一条；等级映射到本项目的中文五档。

**`sqli_probe`**：对每个参数分别发"恒真条件"与"恒假条件"，比对响应长度/特征差异；
再单独探一次错误回显。只判"有没有"，**不取数据、不写数据**。

**`sensitive_scan`**：扫一段文本里的身份证/手机号/邮箱/IP/凭据/私钥，叠加本单位定义（关键词 + 正则）；
证据落盘前按 UTF-8 字符掩码（不是按字节切，否则会把汉字劈成半个）。

**`http_get`**：读一个**授权内**地址 → 状态码、关键响应头（挑白名单那几个）、页面标题、
正文片段（HTML 去标签/去脚本样式，截断）、页面里的链接（解析成绝对地址）。
**池外地址先问边界，直接跳过**，不产生越权记录、不影响其他检查。

**`record_finding`**：模型自己判断出的问题落成发现。`title` 与 `evidence` 必填，
缺证据**拒收**；同目标同标题只更新一条（指纹 `model|<目标>|<标题>`）。

**`ask_user`**：向用户提问并等回答（单选/多选/文本）。只在需要人拿主意时用；
定时/自动巡检禁用（没人回答，问了只会卡住整轮）。

### 9.3 声明格式

`tools\<目录>\<名字>.json`：

```json
{
  "name": "es_search",
  "kind": "外置 · 本机",
  "readonly": true,
  "description": "一句话说明它做什么、什么时候用",
  "source": "~/tools/es/es.exe",
  "schema": { "type": "object", "properties": { "query": { "type": "string" } }, "required": ["query"] },
  "entry": {
    "type": "exec",
    "path": "~/tools/es/es.exe",
    "args": ["-n", "${limit:-20}", "$query"],
    "protocol": "argv",
    "timeout_ms": 15000,
    "quote": false
  }
}
```

- `source: "@app"` = 由主程序自己执行（`<自身> toolhost`，stdin/stdout 走 JSON）。
- 参数展开：`$名字` 必填、`${名字:-默认值}` 带默认；`~/` = 数据目录。
- `protocol`：`argv`（拼命令行）/ `json-stdio`（stdin 进、stdout 出）/ `http`。
- **`quote`（默认 true）**：字符串参数默认加引号并转义 cmd 元字符，防止拼出第二条命令。
  把参数直接拼成查询串的程序（Everything 的 `es.exe`）必须写 `false` ——
  否则引号会进查询，结果"什么都搜不到"。`quote:false` 时仍**剔除** `" & | < > ^ %` 换行，注入不了。
- 工具声明**每次启动覆盖**；用户自己的工具放别的目录（顶层 `tools\` 下任意子目录都会被扫）。

| `runs` | `RUN-` | 运行记录：`scope` `status` `pages_found` `tools_called` `findings_new` `started_at` |
| `reports` | `R-` | 报告：`stats{total,by_severity,by_kind,false_positive}` + `finding_ids[]` + `rules_source` |
| `alerts` | `AL-` | 告警：`finding_id` `channel` `severity` `status` `note` `delivered` |
| `baselines` | `B-` | 内容基线：目标、指纹、快照引用 |
| `diffs` | `D-` | 两次基线的差异 |
| `tasks` / `profiles` / `testcases` / `evals` / `automations` / `chats` | `T-`/`SP-`/… | 任务、敏感信息定义、测试用例、评测、定时任务、会话索引 |

**发现的状态机**：`new` → `confirmed` → `fixed` / `retest_passed` / `retest_failed` / `false_positive`。
复测是**权威结论**：说修好了就推进到 `retest_passed`；判不了保持原状态。

### 10.2 对话转录（v3：快照 + 补丁的追加日志）

`chat\<会话id>.jsonl`，一行一条**操作**（照 VS Code Copilot 的 chatSessions 思路，不兼容旧格式）：

```jsonl
{"kind":0,"v":{…}}                               快照：首行，整个会话对象
{"kind":1,"k":["title"],"v":"新标题"}            把路径上的值换成 v
{"kind":2,"k":["turns"],"v":{…}}                 往路径上的数组追加一项
{"kind":1,"k":["turns",0,"steps",1,"note"],"v":"…"}   改某一轮某一步的字段
```

会话对象（界面按它渲染）：

```json
{ "schema":3, "id":"s-xxxx", "title":"…", "created_at":"…", "updated_at":"…",
  "archived":false, "pinned":false,
  "input":{ "draft":"没发完的话", "attachments":[], "approval":"ask", "model":"" },
  "turns":[ {
     "turnId":"t-0001", "seq":1, "status":"running|complete|error|aborted",
     "started_at":"…", "finished_at":"…",
     "user":{ "blocks":[{"type":"text","text":"…"}] },
     "request":{ "model":"das", "model_name":"恒脑", "approval":"ask",
                 "max_steps":10, "tools":19, "target":"…" },
     "steps":[ {"type":"think","text":"…","at":27}
             | {"type":"tool","name":"pool_list","step_id":"tu-…","args":{},"status":"done",
                "note":"结果首行","duration_ms":379,"artifact":"artifacts/…txt"} ],
     "response":{ "text":"…", "stop_reason":"end_turn", "stop_detail":"已给出结论",
                  "stop_code":2, "steps":1, "tool_calls":1, "llm_ms":2100,
                  "first_byte_ms":1800, "duration_ms":3000, "wait_ms":0,
                  "tokens":{"prompt":18322,"completion":514} } } ] }
```

为什么是这个结构：

- **一轮 (turn) 是单位**，不是"两条消息"。请求与响应成对存，才能回答"这一轮是谁答的、花了多少 token、哪一步最慢"。
- **只追加**：开一轮写骨架、每步写一项、收尾写 response。崩溃只丢最后半行，前面的都还在；也不需要"读全量、改、再重写"。
- **过程随会话落盘**：思考与工具在 `steps[]` 里，切走再切回来、重开历史对话都能原样铺回来。
- **大文本外置**：工具输出超过 2000 字写进 `chat\artifacts\`，消息里只留 `artifact` 引用 —— 否则会话文件会爆。
- **输入状态**：`input.draft/approval/model` 跟着会话存，关掉窗口再回来还是原样。
- 列表 = 扫目录逐个重放（会话量很小）；归档/固定只是补丁，不重写整份。
- 旧格式（v2：message/meta 混写）不再读：启动时自动挪到 `chat\legacy\`，不删用户数据。
- 定时任务运行记录：`time\<任务id>\<时间戳>.jsonl`，一行一轮（规则、范围、检查项、状态、停止原因、步数、请求数、发现数、是否越权、时间）。

### 11.2 SSE 事件

每条都是 `data: {json}\n\n`：

| `type` | 关键字段 | 用途 |
|---|---|---|
| `message_start` | `messageId`, `sessionId`, `timestamp` | 开一条助手消息 |
| `block_start` | `index`, `blockType`(text/tool_use), `toolName`, `toolUseId` | 开一个内容块 |
| `block_delta` | `index`, `delta{type,text}` / `delta{type:"input_json_delta",partialJson}` | 正文增量 / 工具参数增量 |
| `block_stop` | `index` | 结束一个块 |
| `tool_status` | `toolUseId`, `status`(running/done/error/waiting_approval/waiting_answer), `note` | 工具状态 |
| `approval_request` | `id`, `tool`, `args`, `policy` | 请求允许/拒绝 |
| `question_request` | `id`, `payload{message, questions[]}` | 请求回答 |
| `message_stop` | `stopReason`(协议值:`end_turn`/`refusal`), `stopDetail`(人话原因), `durationMs`, `waitMs`, `modelSteps`, `directSteps`, `llmMs` | 收尾 |

**耗时口径**：`durationMs` 由后端算，含等待；`waitMs` 是"等人点允许/点提交"的时间，
界面显示时要减掉 —— 否则"光速跑完但被人耽误 40 秒"会被记成模型慢。

**并行口径**（主流 agent 的形态，前端必须做到）：

- 一轮对话 = 一条 SSE 流。事件的归宿是**发起它的那个会话**，不是"屏幕上当前是谁" ——
  切到别的对话时旧流继续跑，事件继续写进那条消息的 DOM（节点暂时脱离文档）。
- 同一会话内**串行**：上一轮没完再发一句，前端排队、后端用会话锁串行兜底。
- 不同会话**并行**：每个会话有自己的智能体实例、自己的授权范围（`thread_local`）、
  自己的 SSE 上下文（`thread_local`），互不干扰。
- 思考与工具在界面上是一组：工具卡收进它前面那个"思考"块的正文里，
  而不是平铺成一排卡片。

### 11.3 审批与提问的等待机制

两者都是"循环线程停下来等人"，用同一种实现：

- 循环线程在 `WaitForSingleObject` 上等（连接不关，可继续推事件），超时 15 分钟当拒绝/无回答。
- 界面点按钮 → `POST /api/approval` 或 `/api/answer` → `SetEvent` 放行。
- 用**槽位数组**（8 个）而不是单个槽：两个会话同时撞上需要确认的动作时，后来的不该覆盖前一个的等待。
- 无人值守（定时任务）**不提问**；审批则按策略预授权，但"拒绝"策略仍然生效。

## 十二、前端

### 12.1 三层壳

```
起手式(home)  ⇄  任务工作台(work)   →  数据视图(sheet，整页抽屉)
```

- 起手式：大标题 + 一个输入框 + 最近对话卡片。
- 工作台：左侧会话列表 / 中间执行流 + 输入框 / 右侧产物（只留报告摘要）。
- 数据视图：报告 / 日志 / 资产 / 证据 / 配置（抽屉式，从上方压下来）。

### 12.2 执行流的呈现（对齐主流 agent）

- **思考块**：`[第 N 步 · 思考]` 收成一行「› 思考 · 第 N 步」，点开才看全文。
- **工具行**：状态点 + 工具名 + 一句结果 + 折叠箭头；参数与输出点开才展开。
- **正文**：Markdown 渲染；流式按"时间速率"推进（不是每来一块就写一次 DOM），
  合并到一帧刷新；标签页切到后台时直接把已有内容显示完。
- **收尾行**：`消息结束 · 停止原因 X · 调用技能/工具 N 次 · 耗时 Ts · 几步模型/几步直接执行 · 其中模型 Ys`。

### 12.4 关键组件行为

- **审批条**：贴在输入框上方；策略、工具名、参数；「允许/拒绝」。等人时**不算模型在想**。
- **提问卡**：同样位置；标题、说明、单选/多选/文本、提交。等人时也不算模型耗时。
- **页面过期**：令牌每次启动都换 → 旧页面 401 → **自动刷新一次**拿新令牌；

- **设置 → 技能/工具**：一份清单 + 「编辑」直接打开对应文件 + 「新建」落模板再进编辑器。
  **没有图形化表单**（表单只能表达一部分字段，两套数据必然对不上）。
- **设置 → 模型**：选协议（恒脑 / OpenAI 兼容 / Anthropic），非恒脑时隐藏
  `appSecret`/`userAppKey`/智能体 ID/关键词，并把 "appKey（恒脑）" 标签改成 "API Key"。

## 十三、模型接入

`models.json`：

```json
{
  "schema": 1,
  "active": "das",
  "providers": [{
    "id": "das", "name": "恒脑", "kind": "das",
    "base_url": "https://…", "model": "",
    "api_key": "…", "api_secret": "…", "user_app_key": "…",
    "agent_id": "…", "agent_keyword": "",
    "headers": "", "timeout_ms": 180000, "temperature": 0.2, "max_tokens": 0,
    "enabled": true
  }]
}
```

三类协议：

- `das`（恒脑）：签名 = `ts + base64(HMAC-SHA256(app_secret, "{ts}\n{app_secret}\n{app_key}"))`，
  请求头 `appKey` / `sign` / `ext: child_preview:0;reason:1`，body `{id, sid, input, stream:true, order:"routine"}`，端点 `/open/api/v2/agent/execute`。
- `openai`：`/chat/completions`，`Authorization: Bearer`，流式。
- `anthropic`：`/v1/messages`，`x-api-key` + `anthropic-version`，流式。

**只用当前那一条**（配几家由人挑一家用），不悄悄换别家 —— 排查问题最需要知道"到底哪家在回话"。

**超时**：等响应头用配置的超时（默认 180s），收到头之后每片读切成 800ms（让"停止"能在 1 秒内生效），
总时长仍由 deadline 兜住。**不要**把等头砍到 20 秒 —— 长提示词首字节真的会到 60 秒。

**失败冷却**：连续失败后短时间不再重试，避免每步都白等一次超时；失败原因要能显示给用户。

## 十四、报告、导出与告警

- **报告** = 汇总已有发现，按等级/类别统计 + `finding_ids[]` 引用（正文只存一份，避免两处维护）。

  - `pdf`：用本机 Edge/Chrome 无头打印 HTML 得到；找不到浏览器就如实说"先导 HTML 再 Ctrl+P"。

## 十八、重实现时最容易踩的坑

1. **预筛**：发现型请求不预筛 → 站内一条被排除的链接会毁掉整轮（越权中止）。必须"先问边界再请求"。
2. **过宽的失败判定**：把"2 个地址 5xx"当成整站不可达 → 整轮白跑。只在**失败的那条**观察上判。
3. **提示词太长**：直接变成首字节延迟。技能正文 480 字节/条、工具行一句、观察有预算。
4. **等响应头砍太短**：长提示词首字节 60 秒是常态，20 秒上限会把"慢"误判成"断"。
5. **UTF-8 截断**：标题/证据按字节切会切出半个汉字（"重�"）。按字符边界。
6. **审批/提问时间算进模型耗时**：用户会觉得"模型怎么这么慢"，其实在等人。
7. **规则降级冒充智能体**：模型不通就用关键词匹配给结论 —— 已删除，重实现不要引入。
8. **两套数据源**：图形化表单 + 定义文件并存，必然对不上。只保留文件。
9. **`quote` 没做开关**：把参数直接拼成查询串的程序会搜不到东西（es.exe）。
10. **令牌过期只提示不刷新**：用户看到一片空白以为数据丢了。应自动刷新一次。
11. **出厂工具声明"缺了才补"**：版本升级后旧声明残留，指向已删除的 exe，工具静默失效。
12. **并发覆盖审批槽**：两个会话同时等确认时互相覆盖 → 前一轮永远等不到答复。用槽位数组。

### A.5 工具返回契约

所有工具都返回三段（走 `toolhost` 时是 stdout 的一个 JSON）：

```json

  "text": "给人/给模型看的结果正文（进提示词、进转录）",
  "say":  "一句话说明我在干什么（界面上的工具行摘要）",

## 附录 C · 决策循环的伪代码

```
run_turn(user_text):
  reset_scope(); clear_violation(); clear_cancel(); llm_ms = 0

  # 斜杠命令：直接执行，不经过模型
  if user_text starts with "/":
      return slash_run(user_text)

  observations = []
  for step in 0 .. max_steps-1:
      if cancelled:            stop(CANCELLED); return
      if violation():          stop(OUT_OF_SCOPE); return
      if unreachable(obs):     stop(OUT_OF_SCOPE); return
      if same_as_history(obs): stop(NO_PROGRESS); return
      if trailing_repeat_skills(obs) >= 2: stop(NO_PROGRESS); return

      d = llm_decide(prompt(user_text, observations))
      if d failed:
          stop(ERROR, "模型不可用: " + last_error)
          answer("这一步没做成…可用 / 命令绕过模型")
          return

      if d.kind == ANSWER: answer(d.text); stop(ANSWERED); return
      if d.kind == ASK:    ask(d.text);    stop(NEED_USER); return

      run_step(d.tool, d.args)          # 审批 → 执行 → 观察（append）
      if manual_inspection and last_obs_unchanged and not asked:
