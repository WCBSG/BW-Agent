# 工具清单

工具 = 一次只读动作 + 一次判定。**面向被检目标的工具都只发 `GET`/`HEAD`**,
不写入、不上传、不爆破、不利用;目标必须过授权池,越界在取数通道就被拒绝。

程序自带 15 个工具,还支持在数据目录里加外部工具与 MCP 服务器(见文末):
其中 11 个面向被检目标(下表的"侦察类"),另外 4 个是**本机工具** ——
让大模型能读自己的状态、读授权列表、读改本机设置。本机工具不碰被检目标,
但边界更硬:授权池只读、审批只能收紧、周期规则的目标必须在授权池内,
每一次写入都落审计。

这 15 个工具的**实现各自一个源文件**(`agent\src\tools\<名字>.cpp`),
运行时全部由主程序自己(`agent.exe toolhost`)承载:
主程序把 `{"tool","args","context"}` 写进它的 stdin,它按 `tool` 字段分派,
再把结果 JSON 写回 stdout(协议见 [工具协议.md](./工具协议.md))。

为什么不再每个工具一个 exe:每个 exe 都要背一份静态运行库与引擎,
15 个加起来十几 MB,而工具自己的代码只有几 KB。
能力边界靠"注册表里有没有它"来划,不靠进程个数。

## 一、内置工具

### 1.1 侦察类(面向被检目标,只读)

| 工具 | 类型 | 做什么 | 发出的请求 | 判定依据 |
|---|---|---|---|---|
| `site_crawl` | 自研 | 从起点自动发现页面与静态资源,记录类型、状态码、深度、父页面 | 同域 GET,限深限页,2 请求/秒 | 链接抽取 + 同域判定;`ok/redirect/error` 分类 |
| `page_diff` | 自研 | 采集/比对内容基线,给出指纹、标题、字节数、外域主机与可疑外链的增减 | 每页 1 次 GET | 正文指纹(去动态片段)+ 链接抽取;可疑 TLD、裸 IP 落地页 |
| `sensitive_file_probe` | 自研 | 探测误发布的配置/备份/源码/元数据文件,按**内容特征**判定 | 每个落点 1 次 GET,先校准软 404 | 内容特征 + HTTP 状态;自定义错误页不误报 |
| `sensitive_scan` | 自研 | 扫一段文本里的身份证/手机号/邮箱/IP/凭据/私钥,并叠加本单位定义的关键词与正则 | 不发请求(处理已取到的内容) | 正则库 + 本单位定义;证据落盘前按 UTF-8 字符掩码 |
| `dir_probe` | 自研 | 探测常见目录与入口:目录索引、登录入口、暴露文件 | 每个目录 1 次 GET | 目录索引特征、登录表单特征、状态码 |
| `nuclei_scan` | 自研 + **可选调用 nuclei** | 弱配置与漏洞模板:安全响应头、Cookie 属性、版本泄露、错误回显、允许的方法、混合内容;本机有 nuclei 时再跑一轮模板并归并 | 目标 1 次 GET(+ 若有 nuclei,由它发同一目标的只读请求) | 响应头/正文的客观事实;nuclei 用模板结论 |
| `sqli_probe` | 自研(思路参照 sqlmap) | 对带参地址做布尔差分验证,单独验错误回显 | 每参数 2~3 次 GET(恒真/恒假/错误特征) | 响应长度与特征差异;只判"有没有",不取数据 |
| `password_check` | 自研 | 评估口令强度 | 不发请求 | 长度/字符类型/弱口令表 |

### 1.2 本机类(读智能体自己,改本机设置)

| 工具 | 做什么 |
|---|---|
| `fs_read` | 按行读本机文本文件(`path` / `startline` / `endline`),限数据目录与程序目录 |
| `fs_list` | 列目录(子目录 + 文件 + 大小) |
| `fs_write` | 写数据目录里的文件;覆盖前留 `.bak`,不提供删除 |

后四个是「改本机设置」类,能读能写,但边界更硬:

| 工具 | 做什么 | 能不能改 | 边界 |
|---|---|---|---|
| `pool_list` | 列出授权池:允许检查哪些主机、哪些被 `!` 明确禁止、本轮焦点是哪个 | 只读 | 授权池只能由人在界面上加(见下) |
| `agent_info` | 一次拿全:数据目录、当前模型与可用模型数、授权池、审批策略、规则来源、发现/运行/资产/告警/周期条数、技能与工具数 | 只读 | 不发起任何网络请求 |
| `settings_get` | 读设置:`rules`(域清单 / 单域 / 单键)、`approval`、`automation`、`models`、`profile`;默认 `all` 给汇总 | 只读 | 只读本机配置 |
| `settings_set` | 改设置:`rules` 按域存(支持 `key=a.b.c` 深层键,保存即重载)、`automation` 增改删周期规则、`models` 切换当前通道、`approval` 换策略 | **受限写入** | ① 授权池不在可改范围;② 审批只能换成更严的,"全部允许"必须人来点;③ 周期规则的目标必须已在授权池内;④ 每次写入都写审计 |

> 为什么要这三个"读/改设置"的工具:模型以前只能靠猜 —— 猜数据目录、猜用的哪家模型、
> 猜"授权了谁"。用户说"把授权列表都巡检一遍"时它连列表里有什么都不知道,
> 只能反问或只查一个站。现在提示词里摊了授权池、又给了 `pool_list`,
> 它既能说出来,也能照着清单逐个站动手(整池巡检由程序展开成每站一轮,见 README)。

> **这四条边界不是"能力不足",是刻意设计**:模型被页面内容诱导也没用 ——
> 它不能给自己扩授权、不能把审批放宽、不能让一个没授权的站进入周期巡检。
> 其余设置(检测口径、周期、当前模型)可以改,但每条都留审计,
> 事后能回答"这条规则是什么时候、被谁改掉的"。

> 关于"编排开源工具":`nuclei_scan` 会**真的去调** `nuclei.exe`(找 exe 同目录 →
> 数据目录 `tools\` → 数据目录 `bin\` → `PATH`),把命中并进同一份检查清单。
> 调用参数是收窄的:`-c 1 -rl 2`(单并发、2 请求/秒)、`-tags exposure,misconfig,tech`、
> `-etags intrusive,dos,fuzz,brute-force,headless`(排除会改动或压垮目标的那几类)、
> `-ni`(不开 interactsh,不做带外回连)、`-duc`(巡检时不联网更新模板)。
> **本机没装 nuclei 时只用内置检查,并在结果里明确写"这次只有内置检查"**,不假装跑过。

## 二、技能(工具之上的编排,不是工具)

| 技能 | 做什么 | 用到哪些工具 |
|---|---|---|
| `skill_full_inspection` | 一次完整巡检:探活 → 页面发现 → 内容完整性 → 敏感文件 → 目录 → 配置漏洞 | 上表前 6 个 |
| `skill_recon` | 资产与页面发现 | `site_crawl` |
| `skill_leak_check` | 按本单位定义查误发布与泄露 | `sensitive_file_probe` `sensitive_scan` |
| `skill_integrity_check` | 基线比对,判篡改与挂马 | `page_diff` |
| `skill_retest` | 复测:重跑当初的检查,给三态结论 | `page_diff` `sensitive_file_probe` `dir_probe` `nuclei_scan` |
| `skill_report` | 汇总成报告,按等级生成告警(配了 webhook 就投递) | 不发新请求 |
| `skill_evidence` | 核对每条结论的证据/影响/修复与闭环状态 | 不发新请求 |

## 三、外部工具(自己加,不用改代码)

数据目录 `%USERPROFILE%\.bw_agent\tools\<名字>.json`:

```json
{
  "name": "whois_lookup",
  "description": "查域名注册信息",
  "schema": { "type": "object", "properties": { "target": { "type": "string" } } },
  "command": "whois $target",
  "timeout_ms": 20000,
  "allow": true
}
```

- `command` 里的 `$参数名`(`或 ${参数名}`)会被本次调用参数替换。
- `allow` 必须显式为 `true` 才会执行 —— 从别处拷来一份配置不会顺手被执行。
- 登记后模型在工具列表里就能看到它并按需调用,结果进同一条证据链。

## 四、MCP 服务器

数据目录 `mcp.json`:启动时握手 `initialize` → `tools/list`,把对方每个工具登记成
`mcp__<server>__<tool>`,调用走 `tools/call`。同样要求 `"allow": true`。

## 五、能被规则替换的部分(不叫"工具",但直接决定判定)

| 内容 | 位置 | 影响 |
|---|---|---|
| 等级名称与排序 | `rules\*.json` `severity_levels` | 分级、告警阈值 |
| 弱配置检查项 | `rules\*.json` `weak_headers` | `nuclei_scan` 的响应头检查 |
| 敏感落点清单 | `rules\*.json` + 本单位定义 | `sensitive_file_probe` 探什么 |
| 可疑 TLD | `rules\*.json` `suspicious_tlds` | 外链可疑度判定 |
| 弱口令表 / 敏感正则 | `rules\*.json` | `password_check` / `sensitive_scan` |

改这些都不用重新编译;改坏了删掉对应键就回落到出厂默认。

## 六、明确不做的

- 不调用任何会写数据、上传文件、跑字典或做利用的工具(`sqlmap`、`nikto --mutate`、
  爆破类脚本一律不接;`sqli_probe` 只借鉴了布尔差分的方法)。
- 不引入第三方依赖:原生 exe,拷贝即可运行。
- 不对授权池之外的主机发任何请求,包括"顺手探一下"和第三方 DNS/情报接口。
